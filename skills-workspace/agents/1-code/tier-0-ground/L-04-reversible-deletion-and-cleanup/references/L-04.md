# L-04 Reversible deletion and cleanup

**Evidence A: established** · Agent 1 · Code Master (logic) · Tier 0 · Ground

## Why it exists
Deleting is the one operation that re-running cannot undo. Removing dead code, files and dependencies is still essential.

## How it is made
Dry-run list, check nothing depends on the targets (search references, run tests), commit a snapshot or move to trash, delete, verify. Above a threshold (count, size, unfamiliar path) require human confirmation. Treat globs, symlinks and spaces in names as hazards.

## What you can change
Confirmation threshold, trash versus hard delete, allow-listed folders, retention window.

## How it is learned
Modes M5. Rehearse only in sandboxes; build adversarial path tests; study incident reports for failure shapes.

## Proof of mastery
Zero out-of-scope deletions across an adversarial test suite, and every deletion is recoverable.
