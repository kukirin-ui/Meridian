# L-01 Exact reading of code and files

**Evidence B: benchmarked** · Agent 1 · Code Master (logic) · Tier 0 · Ground

## Why it exists
Every change starts with an accurate picture of what exists. Misreading is the root of most bad edits.

## How it is made
Map the repository (tree, entry points, build files), read top-down from the entry point, trace data flow and calls for the task, note invariants and unknowns, then confirm by running or searching instead of guessing. Open the smallest range that answers the question; models lose mid-document detail in long contexts.

## What you can change
Depth versus breadth, tools (grep, symbol index, debugger), how every claim is anchored (file and line).

## How it is learned
Modes M5 M6. Practise on unfamiliar open-source repositories: answer 'where is X handled and why' with file:line anchors, then verify by execution.

## Proof of mastery
Twenty repository questions answered with anchors that match actual behaviour; no invented functions or options.
