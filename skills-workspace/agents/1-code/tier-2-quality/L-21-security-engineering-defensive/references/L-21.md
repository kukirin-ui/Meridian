# L-21 Security engineering (defensive)

**Evidence B: benchmarked** · Agent 1 · Code Master (logic) · Tier 2 · Quality

## Why it exists
Code that works but is exploitable causes real harm. This skill is for defending systems you are authorised to work on.

## How it is made
Threat modelling, input validation, authentication and authorisation, secret handling, memory safety, dependency risk and, for language-model agents, prompt-injection defences and least-privilege tools. Never write malware or attack systems without permission.

## What you can change
Threat model scope, trust boundaries, which actions require approval.

## How it is learned
Modes M5 M6. Review deliberately vulnerable practice applications; fix each class of flaw and add a test.

## Proof of mastery
Seeded vulnerabilities found and fixed with regression tests, and no unauthorised testing.
