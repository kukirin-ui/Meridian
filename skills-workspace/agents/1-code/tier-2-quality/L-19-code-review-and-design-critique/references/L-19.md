# L-19 Code review and design critique

**Evidence B: benchmarked** · Agent 1 · Code Master (logic) · Tier 2 · Quality

## Why it exists
A second look catches defects and spreads understanding.

## How it is made
Check correctness, clarity, tests, security, performance and fit with the design; comment on the code and give reasons; separate must-fix from preference.

## What you can change
Review depth, checklist, who reviews what.

## How it is learned
Modes M2 M5. Review real pull requests and compare with maintainers' comments.

## Proof of mastery
Finds the defects that human reviewers found, with fewer false alarms.
