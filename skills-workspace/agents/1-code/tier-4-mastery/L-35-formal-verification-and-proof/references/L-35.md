# L-35 Formal verification and proof

**Evidence A: established** · Agent 1 · Code Master (logic) · Tier 4 · Mastery

## Why it exists
For critical code, tests show presence of bugs and proofs show absence under stated assumptions.

## How it is made
State the specification formally, model the system, check with a model checker or prove in a proof assistant, and keep the proof in the repository with the code.

## What you can change
Which properties are proved, level of automation, assumptions.

## How it is learned
Modes M3 M5. Work through the interactive textbooks; prove properties of small algorithms and protocols.

## Proof of mastery
Machine-checked proofs of stated properties for a small verified component.
